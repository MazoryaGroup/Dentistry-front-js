# Dentistry Front-End — نسخه Vanilla JavaScript

این پروژه از HTML های ارسالی تبدیل شده است. **هنوز به Laravel API وصل نیست.**

## شروع

```bash
npm install
npm run dev
```

خروجی production:

```bash
npm run build
```

## مسیرهای فعال

| آدرس | فایل | توضیح |
| --- | --- | --- |
| `/` | `pages/Home.js` | صفحه اصلی |
| `/about-us` | `pages/About.js` | درباره ما |
| `/service` | `pages/Service.js` | لیست خدمات |
| `/services/bright-smile-solutions` | `pages/ServiceDetails.js` | تنها نمونه جزئیات خدمت ارسال‌شده |
| `/blog` | `pages/Blog.js` | فهرست مقالات |
| `/post/benefits-of-regular-dental-checkups` | `pages/BlogDetails.js` | نمونه صفحه مقاله ارسال‌شده |
| `/post/choosing-the-best-toothbrush-for-you` | `pages/BlogDetails.js` | همان نمونه؛ متن اصلی در ورودی با slug یکسان نبود |
| `/team` | `pages/Team.js` | تیم |
| `/team/dr-adam-smith` | `pages/TeamDetails.js` | پروفایل نمونه |
| `/contact-us` | `pages/Contact.js` | تماس |
| `/faq` | `pages/Faq.js` | پرسش‌های پرتکرار |

فقط نمونه‌های جزئیات موجود در ورودی تبدیل شده‌اند؛ لینک صفحات جزئیاتی که HTML آن‌ها ارائه نشده، پیام «صفحه هنوز ارائه نشده» نشان می‌دهند و اطلاعات ساختگی نمایش داده نمی‌شود.

## فایل‌های اصلی

- `components/Header.js` — هدر ارسالی به کامپوننت JS تبدیل شده؛ دارای وضعیت لینک فعال
- `components/Footer.js` — فوتر ارسالی به کامپوننت JS تبدیل شده؛ بدون `fetch('/footer.html')`
- `code/router.js` — مسیریابی SPA و Back/Forward
- `code/interactions.js` — تب‌ها، FAQ، گالری و فرم‌ها (بدون ارسال اطلاعات)
- `components/Navbar.js` — منوی موبایل بدون jQuery و Webflow JS
- `asset/css/interactions.css` — حداقل CSS برای حالت‌های تعاملی
- `asset/css/main.css` — **حتماً CSS اصلی Webflow را جایگزین فایل placeholder کنید**
- `asset/img/logo.png` — **فایل لوگوی واقعی را قرار دهید**

## فایل‌های لازم برای طراحی

**در فایل‌های دریافت‌شده CSS اصلی و تصویر لوگو وجود نداشت.** بنابراین فایل `asset/css/main.css` عمداً یک placeholder است و همه کلاس‌های طراحی حفظ شده‌اند تا با اضافه شدن CSS ظاهر اصلی نمایش داده شود.

تصاویر موجود در HTML به صورت CDN اصلی Webflow (`cdn.prod.website-files.com`) تنظیم شده‌اند تا در صورت دسترسی اینترنت نمایش داده شوند. برای کار کردن بدون اینترنت باید تصاویر و فونت‌های اصلی نیز به پروژه منتقل و مسیرها محلی شوند.

## فرم‌ها

تمام فرم‌های Contact و Footer نمایشی هستند. Submit به سرور انجام نمی‌شود و پیام «فرم هنوز به سرور وصل نیست» نشان داده می‌شود؛ هیچ موفقیت ساختگی‌ای نمایش داده نمی‌شود.

## استقرار

Vite با `npm run build` پوشه `dist/` را می‌سازد. روی Nginx / Apache باید برای مسیرهای SPA مثل `/team/dr-adam-smith` درخواست‌ها به `index.html` برگردند. در Nginx:

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

> نکته: جزئیات نمونه Blog و Service در HTML های اصلی از نظر عنوان، مسیر و محتوای داخلی مغایرت‌هایی داشتند؛ محتوا عیناً حفظ شده و اطلاعات واقعی/جدید ساخته نشده است.

## صفحات جدید بیمار (13 اکتبر 2026)

پنج صفحه زیر به پروژه اضافه شدند. این صفحات طراحی مستقل و CSS اختصاصی دارند و روی کد صفحات عمومی تأثیری نمی‌گذارند.

| مسیر | فایل | وضعیت |
| --- | --- | --- |
| `/login` | `pages/Login.js` | ورود با اعتبارسنجی فرم، بدون تأیید هویت |
| `/register` | `pages/Register.js` | ثبت‌نام با تأیید تکرار رمز، بدون ایجاد حساب |
| `/forgot-password` | `pages/ForgotPassword.js` | بازیابی رمز، بدون ارسال پیام یا ایمیل |
| `/dashboard` | `pages/Dashboard.js` | داشبورد نمونه بیمار، با نوبت‌ها، درمان‌ها، امور مالی، پروفایل |
| `/checkout` | `pages/Checkout.js` | خلاصه نمونه نوبت، انتخاب خدمت و بررسی هزینه؛ بدون رزرو و پرداخت |

کامپوننت مشترک این صفحات `components/PortalUI.js` و استایل آن‌ها `asset/css/portal.css` است. فقط `code/router.js` برای ثبت مسیرهای جدید تغییر کرده است.

**مهم:** هیچ حسابی احراز هویت نمی‌شود، رمزها جایی ذخیره نمی‌شوند، نوبتی ایجاد نمی‌شود و پولی جابه‌جا نمی‌شود. قیمت‌ها، ساعت‌ها، نمونه بیمار و رکوردهای داخل داشبورد همگی صرفاً اطلاعات نمایشی و ساختگی هستند. قبل از انتشار سایت، باید Laravel API، سیستم احراز هویت امن، مدیریت نوبت‌ها، قیمت‌های واقعی، درگاه پرداخت و مقررات حریم خصوصی متصل/تکمیل شوند.

برای تجربه مشابه صفحه طراحی‌شده، صفحات `/login`، `/register`، `/forgot-password` و `/dashboard` با چیدمان مستقل از هدر/فوتر عمومی باز می‌شوند. Checkout هدر و فوتر عمومی را حفظ می‌کند.

**توجه:** برای تطبیق ظاهر کل سایت، هنوز CSS اصلی Webflow و لوگوی واقعی لازم است. پنج صفحه جدید به صورت مستقل در Chromium با CSS اختصاصی خودشان در دسکتاپ و موبایل تست شده‌اند؛ اما Build واقعی Vite در محیط ساخت به دلیل نصب‌نشدن وابستگی‌ها تأیید نشده است.


## فارسی و انگلیسی (i18n)

- دکمه‌های `FA / EN` در Header، فرم‌های ورود/ثبت‌نام/بازیابی، و داشبورد وجود دارند.
- پیش‌فرض انگلیسی است تا با طرح Webflow اولیه هماهنگ باشد.
- زبان در `localStorage` و `?lang=fa` / `?lang=en` نگهداری می‌شود؛ پارامتر URL در اولویت است.
- `code/i18n.js`: مدیریت زبان، راست‌چین/چپ‌چین، ترجمه UI، قالب‌بندی پول.
- `lang/fa.js`: کلیدهای عبارت انگلیسی و ترجمه فارسی؛ `lang/en.js`: فایل زبان اصلی.
- `asset/css/i18n.css`: کلید تغییر زبان و قواعد RTL.
- افزودن ترجمه برای صفحه‌های Webflow: معادل عبارت انگلیسی را به `lang/fa.js` اضافه کن.
- ترجمه عبارات مشترک، ناوبری، فرم‌های بیمار، Checkout، داشبورد و بخش‌های پرتکرار انجام شده؛ همه متن‌های طولانی قالب Webflow هنوز نهایی یا ترجمه نشده‌اند و نیازمند محتوای تأییدشده کلینیک هستند.
- تمام داده‌ها و فرم‌ها همچنان نمایشی هستند؛ API و پرداخت واقعی متصل نشده‌اند.
